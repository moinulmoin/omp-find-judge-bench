Why thinking & fast mode didn't move the numbers

Captured the actual request bodies with PI_REQ_DEBUG=1. The find judge calls chat models with disableReasoning: true and no service tier (packages/ai/src/judgment/chat.ts), so the role's :low/:medium/:high suffix and tier.openai: priority are dropped before the wire.

GLM 5.3 Flash: the 38s → fix

A models.yml provider pointed at z.ai's Anthropic-compatible endpoint (api.z.ai/api/anthropic). omp sends thinking: disabled; z.ai docs say GLM 5.3 can't disable thinking, so it silently ran at its default effort, max — one response: 2,317 chars reasoning for 601 chars of answer.

The same model on z.ai's OpenAI-compatible endpoint (api.z.ai/api/coding/paas/v4, defined here as provider zai-oai) gets reasoning_effort: "low", and z.ai honors it.

Still ~31s on the real repo: where the time goes

  • GLM-5.3 always thinks, even at low. The first round of questions (ranking files by name, ~6.5k prompt tokens each) produced 566–857 reasoning tokens per request at ~67 tok/s, so 14–18s per request.
  • find runs three rounds one after another. Each round waits for its slowest request: ~17s + ~9s + ~5s ≈ 31s. jev returns calibrated yes/no scores without generating reasoning text, so each round takes well under a second.
  • Burst limit, small effect. z.ai answered 4–7 of the requests in each run with 429 {"code":"1302","message":"Rate limit reached for requests"} when find sent up to 16 at once. That's a per-second request limit, not your plan quota; the retries add about 1–2s.

Recommendation

  1. Fastest and most consistent: typesafe/jev-latest (paid TypeSafe judge, built for find).
  2. Best no-extra-cost option on a Claude subscription: anthropic/claude-haiku-5-5:medium. Set retry.fallbackChains.judge: [] if you don't want omp's built-in judge fallback chain (which starts with jev) to kick in.
  3. Don't use GLM or Luna as the find judge: the in-session find tool aborts at 20s, so both would time out on real repos.
Method: omp find --json via bench/omp-find-bench · rounds interleaved across configs · judgment cache moved aside and restored · raw runs in data/runs.json · 3 runs per config, one query: enough to show the request bug, not a model leaderboard.
